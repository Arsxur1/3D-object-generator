# Пре-регистрация: инкремент 9 — проверка правил выбора порогов на новых пациентах

> Документ зафиксирован в git **до** загрузки и анализа тестовых данных. Любое
> отклонение от протокола будет явно указано в отчёте. Цель — чтобы выбор правила,
> порогов и критериев успеха не мог подстроиться под тестовые результаты.

## Вопрос

В инкременте 8 правило выбора порогов «strict» (минимум ложных тревог при полной
чувствительности на обучении) выбирало «острый угол» сетки и на отложенной смешанной
выборке теряло 1–2 приступа из 15. Гипотеза: правило, которое **тратит бюджет ложных
тревог на запас чувствительности**, переносится на новых пациентов лучше.

## Правила выбора (код: `neurolens.evaluation.tune.TuneResult.select`)

* **strict** — FA/ч ≤ 1, макс. чувствительность, затем мин. FA, затем мин. латентность.
* **robust** — то же, но по *худшему соседу* в сетке (каждый порог на шаг в обе стороны)
  и для чувствительности, и для FA.
* **margin** (**первичное**) — собственный FA/ч ≤ 1, макс. собственная чувствительность,
  затем макс. *чувствительность худшего соседа* (запас до пропуска приступа), затем
  мин. FA, мин. латентность.

Почему первичное — margin (решено на обучающих данных, до теста): «robust» уже на
обучении жертвует чувствительностью (оффлайн 0.94, real-time 0.85), что противоречит
клиническому приоритету (ТЗ §10); из правил с полной обучающей чувствительностью у
margin наибольший запас (худший сосед 0.85 против 0.71 у strict).

## Тестовая выборка (правило отбора — без учёта качества детекции)

* **CHB-MIT:** все пациенты, не использованные ранее, у которых (файлы с приступами +
  первые 3 файла без приступов) ≤ 0.5 ГБ, **кроме chb21** (тот же ребёнок, что chb01,

* **Siena:** все неиспользованные пациенты с записью ≤ 360 мин: **PN05, PN16, PN17**

## Метрики и анализ

* Оценка — как в инкременте 8: событийная OVLP [onset − 30 с, offset + 60 с], слияние
  детекций < 10 с; FA/ч; латентность (медиана, p90). Real-time — воспроизведение трасс
  монитора (побитово эквивалентно живому монитору).
* Для каждого режима (оффлайн, real-time) — пороги по умолчанию, strict, robust, margin.
* Сводно по всем 13 пациентам и отдельно CHB-MIT / Siena; по-пациентно; 95% ДИ
  Клоппера–Пирсона для чувствительности.

## Гипотезы

* **H1 (первичная):** оффлайн чувствительность margin ≥ strict на тестовой выборке.
* **H2:** оффлайн FA/ч margin ≤ 1.0 на тестовой выборке.
* **H3:** пороги по умолчанию дают наибольшую чувствительность, но FA/ч > 1 в обоих режимах.
* **H4:** real-time margin: чувствительность ≥ 0.9 и FA/ч ≤ 1.0.

## Правило решения (зафиксировано заранее)

* **Тревоги монитора (real-time):** если margin на тестовой выборке теряет **не более
  5% относительной чувствительности** против порогов по умолчанию (чувств.(margin) ≥
  0.95 × чувств.(default)) **и** FA/ч ≤ 1.0 — его пороги становятся **дефолтом
  монитора** (`configs/realtime.yaml`: `threshold_overrides` + persistence). Иначе
  дефолты монитора не меняются, подобранные остаются опциональным оверрайдом.
* **Оффлайн-анализ:** пороги в `thresholds.yaml` не меняются при любом исходе (отчёт
  читает врач; ложная детекция дешевле пропуска); `configs/thresholds.physionet.yaml`
  перезаписывается порогами margin.
* Результаты публикуются полностью, включая неподтверждённые гипотезы.
