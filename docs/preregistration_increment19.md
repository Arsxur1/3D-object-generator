# Пре-регистрация, инкремент 19: повторяемость разрядов по обученной модели

> Зафиксировано и опубликовано **до** запуска любого пайплайна на свежей подвыборке 19
> (`docs/increment19_fresh_ids.json`).

## 1. Изменение

До сих пор кандидат-«спайк» эвристики становился патологическим, если обученная модель
(`ied_gbm_v1`) оценивала **этот кандидат** ≥ 0.95. Эвристика выдаёт не более 8 кандидатов на
запись, отобранных по её собственной уверенности, а не по вероятности модели; это была главная
оставшаяся причина ложной «картины отклонений» (21 из 54 на свежей выборке инкремента 18).

Новое правило (клиническое: разряды сообщаются, когда они **повторяются**): обученная модель
просматривает **всю запись**; кандидаты-спайки патологичны, только если в записи ≥ **2** отдельных
детекции с вероятностью ≥ **0.98** (`configs/ied.yaml: recurrent_threshold`, `recurrent_min_count`).
Иначе — «сомнительно» (остаются в отчёте). Текст отчёта сообщает число таких детекций.

Разработка (подвыборка seed 17): доля записей с ≥ 2 детекциями ≥ 0.98 — 0.12 нормальных и 0.54
аномальных (прежнее правило: 0.12 / 0.46). Заключение: специфичность 0.658 → 0.650,
чувствительность 0.787 → **0.812** (`docs/increment19_dev_v6.json`). Порог 0.98 и число 2 выбраны
на разработке (сравнивались 0.95/0.98/0.99 и 1/2/3/5).

## 2. Проверка

Свежая подвыборка обучающей части NMT, seed 19, **не пересекающаяся** ни с разработкой, ни с
подвыборкой инкремента 18: 150 нормальных и 100 аномальных записей. Сравнение на тех же записях:
пайплайн этого коммита против пайплайна инкремента 18 (коммит c24186e), оба через
`scripts/run_routine_ids.py`.

## 3. Гипотезы (`evaluation/prereg19.py`)

* **H1** — прирост чувствительности ≥ **0.03**.
* **H2** — специфичность не ниже, чем у инкремента 18, более чем на **0.03**.
* **H3** — специфичность ≥ **0.55**.

## 4. Правило решения (`prereg19.apply_decision`)

* **H1 ∧ H2 ∧ H3** → правило остаётся; `configs/impression.yaml` получает специфичность и
  чувствительность на подвыборке 19.
* Иначе → `configs/ied.yaml: recurrent_threshold: null` (возврат к оценке отдельного кандидата
  ≥ 0.95); числа в `impression.yaml` — инкремента 18.
