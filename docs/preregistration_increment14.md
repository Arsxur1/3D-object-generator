# Пре-регистрация: инкремент 14 — стадировщик сна для клинических производных (CAP)

> Зафиксировано в git **до загрузки тестовых записей**. Обучение — только на данных, уже
> использованных ранее (29 записей CAP инкремента 13b и Sleep-EDF); тестовые записи CAP не
> использовались ни разу. Код — `datasets/capsleep.select_test_records_14`,
> `evaluation/prereg14.py`; замороженная модель добавляется в «Заморожено» до загрузки теста.

## Вопрос

Инкремент 13b: модель, обученная на Fpz-Cz/Pz-Oz, на клинических парасагиттальных
производных даёт каппу 0.545 — такие записи не стадируются. Даст ли модель, обученная на
клинических производных, достаточное качество у **новых** пациентов CAP?

## Обучение (зафиксировано)

* Признаки и бустинг — как в инкременте 13 (те же 43 признака × контекст ±2, 200 итераций).
* Производные клинических записей — как в 13b: Fp2−C4, P4−O2, ROC-LOC (левая цепочка при
  отсутствии правой).
* Кандидаты: **A** — 29 записей CAP инкремента 13b; **B** — те же 29 + все 153 ночи
  Sleep-EDF (обе половины; их тест уже использован в инкременте 13).
* Выбор: 5-кратная кросс-валидация по записям CAP (фолд = позиция записи в отборе 13b mod 5;
  в варианте B Sleep-EDF всегда в обучении); метрика — каппа на 29 записях CAP; выбирается
  кандидат с большей каппой (при равенстве — A). Финальная модель —
  `configs/models/sleep_stager_clinical_v1.json` на всех данных выбранного кандидата.

## Тест (зафиксировано)

Пригодные записи CAP (цепочка + ROC-LOC), **не** использованные в 13b; в каждой группе по
номеру — каждая вторая (1-я, 3-я, …). Итого **34 записи**: n11, ins5, ins7, ins9, narco5, nfle5, nfle7, nfle9, nfle11, nfle13, nfle15, nfle17, nfle19, nfle21, nfle23, nfle26, nfle28, nfle30, nfle32, nfle35, nfle37, nfle39, plm5, plm7, plm9, rbd5, rbd8, rbd10, rbd12, rbd14, rbd16, rbd18, rbd20, rbd22.

```bash
neurolens sleep cap14 --assess --out out_eval/prereg14
```

На тех же записях сравниваются клиническая модель, v1 (инкремент 13, без дообучения) и
правиловый стадировщик. Записи скачиваются по одной, превращаются в признаки и удаляются.

## Гипотезы

* **H1 (первичная):** каппа клинической модели ≥ 0.60.
* **H2:** каппа клинической ≥ каппы v1 + 0.05.
* **H3 (вторичная, перенос):** |каппа теста − каппа кросс-валидации| ≤ 0.05.

## Правило решения

Если верны H1 и H2 — `configs/sleep.yaml`: `parasagittal_fallback: true`,
`parasagittal_model: configs/models/sleep_stager_clinical_v1.json` (записи без центральной
линии стадируются клинической моделью; записи с центральной линией — по-прежнему v1). Иначе —
без изменений (не стадируются). Применение — `prereg14.apply_decision`.

Оговорка: тест богат пациентами с эпилепсией (17) и нарушением поведения в фазе REM (9);
здоровых — 1. Результат относится к этому составу.
