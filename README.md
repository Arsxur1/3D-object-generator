# NeuroLens — система детекции и интерпретации ЭЭГ

> **Статус:** MVP-фундамент + сквозной скелет пайплайна (по §18 ТЗ). Каркас всех
> 6 слоёв за интерфейсами, реальные классические/qEEG-алгоритмы для ядра,
> детерминированный синтетический вход, заземлённый LLM-протокол RU/UZ.
> Это **инструмент поддержки решений врача**, не диагностическое заключение.

⚕ **Дисклеймер.** NeuroLens не принимает клинических решений. В режиме по умолчанию
(A) итоговая интерпретация всегда требует просмотра квалифицированным
нейрофизиологом/реаниматологом. Система «regulator-ready» (трассируемость,
версионирование), но не сертифицирована и не предназначена для клинического
применения без валидации.

## Что уже работает

Сквозной прогон на одном EDF: **приём → предобработка/качество/артефакты →
количественная ЭЭГ (спектр, DSA, aEEG, супрессия) → детекция (фон, иктальный
ритм, **периодические/ритмические паттерны ACNS: GPDs/LPDs/BIPDs/LRDA/GRDA с
модификаторами и IIC**, burst-suppression, трифазные, **FIRDA**, **extreme delta
brush**, ЭКГ-артефакт, IED, **доброкачественные варианты (wicket)**) → счётчик
судорожной нагрузки → причинно-следственный и физиологический разбор (каузальный
граф, разведение артефакт/вариант↔IED) → заземлённый LLM-протокол RU/UZ →
JSON + текстовый протокол + графики**.

- **6 слоёв за контрактами** (`src/neurolens/layer1_ingest … layer6_interpret`) —
  заменяемые модули.
- **Контракты данных** — pydantic v2 (`src/neurolens/contracts`), JSON-схемы в
  `schemas/` (генерируются из моделей).
- **Конфиги, ничего не хардкодится** (`configs/`): монтажи (double banana,
  поперечный, референциальный), фильтры (режектор 50/60 Гц), пороги и гейты
  режима B, возрастные нормы, терминология ACNS, **база нейро-правил** (4 цепочки).
- **Критические находки (§10)** поднимаются независимо от LLM и режима.
- **Заземление (§9, §16):** каждое утверждение LLM привязано к признаку/событию/
  ребру графа; незаземлённое отбрасывается автоматически.
- **Режимы A/B (§2):** A — поддержка решений (по умолчанию); B — автономный, но
  только при прохождении гейтов (иначе эскалация «требуется просмотр врача»).
- **Real-time cEEG (§2 под-режим, §16):** потоковый мониторинг окнами с overlap →
  **тревоги** (судороги, эпилептический статус, IIC, burst-suppression) с контролем
  частоты ложных тревог/час (персистентность + рефрактерность + лимиты) и **фрагментом
  ЭЭГ** к каждой тревоге; накопление судорожной нагрузки и бюджет латентности.
- **REST API (§12, §14):** FastAPI-сервис над пайплайном и монитором с обязательными
  для §12 требованиями — **деидентификация PHI** перед выдачей, **аудит-лог**,
  **версионирование**; эндпоинты analyze/monitor/feedback/schemas. Ядро — edge/локально,
  облако — тяжёлые модели/LLM.
- **Калибровка уверенности (§13, §16):** temperature scaling по коду события + метрики
  ECE/MCE/Brier; сборка калибровки из лога правок нейрофизиолога; калиброванные confidence
  идут в каузальный граф, gate режима B и тревоги — чтобы пороги были надёжны.
- **Неонатальная специализация (§1, §6):** классификация паттерна aEEG (Hellström-Westas:
  CNV/DNV/BS/CLV/FT), цикличность сон-бодрствование (SWC), маутрационные нормы по ПМВ и
  **возраст-зависимая физиологичность** (прерывистость нормальна у недоношенного,
  патологична у доношенного); неонатальный редуцированный монтаж; правило BS→HIE.
- **Реальные данные PhysioNet (§16):** загрузка CHB-MIT/Siena с проверкой SHA-256,
  докачкой и вежливым лимитом соединений; биполярные архивы → точная средняя
  референция; событийная оценка (чувствительность, ложные тревоги/ч, латентность);
  точное воспроизведение трасс монитора; длинные записи — поблочно в пределах памяти.
- **Пре-регистрированные проверки:** протокол, пороги/модели, отбор новых пациентов,
  гипотезы и код анализа фиксируются в git до загрузки тестовых данных
  (`docs/preregistration_increment9.md`, `docs/preregistration_increment10.md`).
- **Обученный детектор приступов (§7.3, §13):** градиентный бустинг по 23 каузальным
  признакам, JSON-модель + numpy-исполнение, один детектор оффлайн и в мониторе,
  калибровка Platt; включение по умолчанию — по пре-регистрированному правилу
  (`docs/learned_detector.md`, `docs/model_card_ictal_gbm.md`).
- **Слой 6 — реальный LLM:** провайдер Anthropic (schema-constrained) при наличии
  `ANTHROPIC_API_KEY`; иначе детерминированный заземлённый провайдер (оффлайн,
  воспроизводимо, используется в тестах).

## Архитектура (6 слоёв, §3 ТЗ)

```
[1] Приём/нормализация      layer1_ingest    EDF/EDF+ → единое представление сигнала
[2] Предобработка/качество  layer2_preprocess фильтры, режектор, ререференс, монтаж-движок,
                                              плохие каналы, SQI, флагирование артефактов (+ICA-хук)
[3] Количественная ЭЭГ       layer3_features  спектр, SEF95, PAF, энтропия, DSA, aEEG,
                                              суппрессия/burst-suppression, асимметрия, нормы
[4] Детекция паттернов       layer4_detect    диффузное/очаговое замедление, иктальный ритм,
                                              ACNS-паттерны (GPDs/LPDs/BIPDs/LRDA/GRDA + IIC),
                                              burst-suppression, трифазные, FIRDA, extreme delta
                                              brush, ЭКГ-артефакт, IED, wicket; судорожная нагрузка
[5] Каузальный/физио-анализ  layer5_reasoning каузальный граф (networkx), физиологично/патологично,
                                              правдоподобность, разведение артефакт/вариант↔IED
[6] Интерпретация/объяснение layer6_interpret заземлённый протокол RU/UZ (Anthropic / детерминир.)
```

## Быстрый старт

```bash
# 1) сгенерировать детерминированный синтетический EDF
python data/synthetic/make_synthetic_edf.py            # → data/synthetic/demo.edf
# сценарий с периодическими паттернами ACNS (LPDs/GRDA/FIRDA/EDB/wicket):
python data/synthetic/make_synthetic_edf.py --scenario periodic -o periodic.edf
# неонатальный сценарий (прерывистый фон + SWC); анализ с ПМВ активирует неонат. разбор:
python data/synthetic/make_synthetic_edf.py --scenario neonatal -o neo.edf
neurolens analyze neo.edf --pma 28 --montage neonatal --out out_neo    # недоношенный: норма для возраста
neurolens analyze neo.edf --pma 40 --montage neonatal --out out_neo    # доношенный: та же запись — патология

# 2) сквозной демо-прогон (печатает протокол RU/UZ, пишет out_demo/)
python examples/run_demo.py

# либо через CLI:
neurolens demo --out out_demo
neurolens analyze data/synthetic/demo.edf --mode A --montage double_banana --out out_demo
neurolens export-schemas schemas

# real-time мониторинг (cEEG) с тревогами и фрагментами ЭЭГ:
neurolens monitor data/synthetic/demo.edf --out out_rt          # быстрый повтор
neurolens monitor data/synthetic/demo.edf --realtime --out out_rt  # в темпе wall-clock
```

Выход (`out_demo/`, все форматы §11): `result.json` (структурированный вывод §11.1),
`protocol_ru_uz.txt` (протокол с цепочкой рассуждений и дисклеймером),
`curves.png` (кривые в монтаже с отметками событий), `dsa_aeeg.png` (тренд DSA + aEEG),
`topomap.png` (топокарты мощности по диапазонам), `causal_graph.png` (каузальный граф),
`report.pdf` (сводный PDF-отчёт RU/UZ с ключевыми кривыми, топокартами, графом и заключением).

### Калибровка уверенности (§13)

```bash
# собрать калибровку из лога правок нейрофизиолога (confirm/reject + confidence)
neurolens calibrate --feedback feedback.jsonl --out configs/calibration.json
# применить калиброванные confidence при анализе (gate режима B и тревоги — надёжнее)
neurolens analyze data/synthetic/demo.edf --calibration configs/calibration.json --out out_demo
```

`configs/calibration.json` — identity по умолчанию (no-op); реальные температуры
фитятся из feedback-лога (`/feedback` эндпоинт или CLI).

### REST API (§12)

```bash
python -m pip install -e ".[api]"          # fastapi + uvicorn + multipart
neurolens serve --host 127.0.0.1 --port 8000
# GET  /health · /version · /config/montages · /schemas/{name}
# POST /analyze {path,mode,montage,provider,age_years,...}   (или /analyze/upload — multipart)
# POST /monitor {path,montage,window_s,step_s}
# POST /feedback {recording_id,target_kind,target_ref,action,...}
```

Результаты **деидентифицированы** (имя файла → `subject_id`-хэш), каждый запрос — в
аудит-лог (`NEUROLENS_AUDIT_LOG`); соль деида — `NEUROLENS_DEID_SALT`.

### Реальные данные PhysioNet: валидация и подбор порогов (§16)

```bash
# список записей и приступов (CHB-MIT; также --db siena)
neurolens physionet list --subjects chb01
# скачать записи с приступами + 2 без приступов на пациента (кэш data/physionet/, SHA-256)
neurolens physionet fetch --subjects chb01,chb03,chb05 --n-free 2
# оценка против экспертной разметки: чувствительность, FA/час, латентность
neurolens evaluate --subjects chb05 --realtime --out out_eval/chb05
# Siena (взрослые): докачка больших файлов по HTTP Range, проверка SHA-256
neurolens physionet fetch --db siena --subjects PN00,PN11,PN12 --max-gb 2.5
# подбор порогов на одних пациентах, отчёт на других (можно смешивать базы: siena:PN00);
# --realtime отдельно подбирает рабочую точку монитора; --write сохраняет оверрайды
neurolens tune --train chb01,chb03,siena:PN00 --test chb05,chb08,siena:PN11,siena:PN12 \
  --realtime --write --out out_eval/tune
# применить подобранные пороги
neurolens analyze rec.edf --overrides configs/thresholds.physionet.yaml
neurolens monitor rec.edf --overrides configs/thresholds.physionet.yaml
```

Биполярные архивы (CHB-MIT) автоматически переводятся в точную среднюю референцию.
Итог пре-регистрированной проверки на 13 новых пациентах (92 ч, 66 приступов):
пороги по умолчанию находят 79% приступов оффлайн (10 FA/ч) и 71% в мониторе (5 FA/ч);
подобранные пороги на новых пациентах снижают чувствительность до 33–45% — оверрайд
**не рекомендуется**. Подробно: `docs/validation_physionet.md`,
`docs/preregistration_increment9.md`.

### Обученный детектор приступов (§7.3, §13)

Градиентный бустинг по 23 каузальным признакам эпох (амплитуда относительно
собственной базовой линии канала, ритмичность, частота, мощности, распространённость),
обученный на 31 пациенте PhysioNet (модели v2, инкремент 11). Модель хранится в JSON и исполняется numpy;
scikit-learn нужен только для обучения (`pip install -e '.[ml]'`). Один и тот же
детектор работает оффлайн и в мониторе (потоковые признаки побитово совпадают с
оффлайн).

```bash
# пре-регистрированная проверка на новых пациентах (модели заморожены, SHA-256)
neurolens ml-eval --test chb06,siena:PN10 --frozen docs/preregistration_increment11_frozen.json \
  --assess --analysis prereg11 --out out_eval/ml   # --stream-cache: возобновление после сбоя
```

```python
from neurolens.pipeline.pipeline import Pipeline
from neurolens.realtime.monitor import RealtimeMonitor
Pipeline()                      # по умолчанию: обученный детектор (configs/ml.yaml)
RealtimeMonitor()               # монитор: по умолчанию тоже обученный (инкремент 11)
Pipeline(learned=False)         # пороговый детектор — явно
RealtimeMonitor(learned=False)
RealtimeMonitor(patient=PatientInfo(postmenstrual_age_weeks=40))  # новорождённый: неонатальная модель
```

**Статус:** обученный детектор — **по умолчанию и оффлайн, и в мониторе** (решение
пре-регистрированного инкремента 11 на 6 последних неиспользованных пациентах, 33
приступа): монитор v2 0.70 при 3.3 FA/ч против порогового 0.52 при 4.1; оффлайн v2 0.88
при 7.9 FA/ч против 0.58 при 10.2. Инкремент 10 (11 пациентов, 108 приступов): оффлайн
0.94 при 8.9 против 0.90 при 9.8. На объединённых 17 новых пациентах (141 приступ)
модель v1 нашла 0.92 оффлайн / 0.85 в мониторе против 0.82 / 0.77 у порогового.
Переключатели — `configs/ml.yaml`. Метод — `docs/learned_detector.md`; карточка модели —
`docs/model_card_ictal_gbm.md`; результаты — `docs/increment10_report.md`,
`docs/increment11_report.md`.

### Реальный LLM (Anthropic)

```bash
export ANTHROPIC_API_KEY=...            # ключ
export NEUROLENS_LLM_MODEL=claude-...   # опционально: модель
neurolens analyze demo.edf --provider anthropic --out out_demo
```

Провайдер `auto` (по умолчанию) использует Anthropic при наличии ключа, иначе —
детерминированный провайдер. При ошибке API происходит безопасный фолбэк.
Ответ модели проходит ту же проверку заземления — выдумки отбрасываются.

## Синтетический вход

`data/synthetic/make_synthetic_edf.py` создаёт 21-канальный EDF (10-20, 256 Гц,
6 мин) с внедрёнными паттернами: нормальный альфа-фон → диффузное замедление →
левосторонняя асимметрия → иктальный ритм (эволюция) → трифазные волны →
burst-suppression; наложенный ЭКГ-артефакт. Полностью оффлайн и воспроизводимо.
CLI/пайплайн также принимают путь к реальному EDF.

## Тесты

```bash
python -m pytest -q
```

Покрывают: контракты/схемы, детерминизм EDF, приём и нормализацию каналов,
фильтры/режектор, монтаж-движок, спектральные признаки, суппрессию, детекторы на
внедрённых паттернах, rules-engine (ожидаемые каузальные рёбра, разведение
ЭКГ↔IED), заземление (отбрасывание незаземлённого), и e2e (JSON проходит схемы,
критические находки, гейт режима B).

## Дорожная карта

**Сделано (этот проход):** §18.1–18.4 — структура, контракты/схемы, конфиги
(монтажи + правила), скелет пайплайна на одном EDF, каузальный разбор,
заземлённый протокол RU/UZ, все базовые форматы вывода, тесты.

**Инкремент 2 (сделано):** углубление §7 — периодические/ритмические паттерны ACNS
(GPDs/LPDs/BIPDs/LRDA/GRDA) с модификаторами (частота/распространённость/плюс-признаки)
и меткой IIC; FIRDA; extreme delta brush; счётчик судорожной нагрузки; разведение
доброкачественных вариантов (wicket) и возрастных норм от эпилептиформного.

**Инкремент 3 (сделано):** все форматы вывода §11 — топокарты мощности по диапазонам,
визуализация каузального графа (физиологично/патологично, критические узлы) и сводный
PDF-отчёт RU/UZ (шрифт DejaVu для кириллицы) с ключевыми кривыми, DSA/aEEG, графом и заключением.

**Инкремент 4 (сделано):** real-time cEEG (§2/§4/§10/§16) — потоковый источник
(повтор EDF; LSL-интерфейс опционален), буфер окон с overlap, тревоги
(судороги/статус/IIC/burst-suppression) с контролем FA/час (персистентность,
рефрактерность, лимиты) и фрагментом ЭЭГ, скользящий базлайн для потоковой детекции
судорог, бюджет латентности, CLI `monitor`.

**Инкремент 5 (сделано):** REST API (§12/§14) — FastAPI-сервис (analyze/monitor/
feedback/schemas/health/version), деидентификация PHI, аудит-лог, версионирование,
CLI `serve`; эндпоинт правок нейрофизиолога (§13).

**Инкремент 6 (сделано):** калибровка уверенности (§13/§16) — ECE/MCE/Brier +
temperature scaling per-code, сборка из feedback-лога, интеграция в пайплайн
(калиброванный gate режима B), CLI `calibrate`.

**Инкремент 7 (сделано):** неонатальная специализация (§1/§6) — классификация aEEG
(Hellström-Westas), SWC, маутрационные нормы по ПМВ, возраст-зависимая физиологичность,
неонатальный монтаж/сценарий, правило BS→HIE.

**Инкремент 8 (сделано):** реальные данные PhysioNet (§16) — клиент (кэш, SHA-256,
докачка), парсеры CHB-MIT/Siena, биполярные архивы → средняя референция, событийная
оценка, подбор порогов, отдельная рабочая точка монитора (воспроизведение трасс),
смешанное обучение дети + взрослые.

**Инкремент 9 (сделано):** пре-регистрированная проверка правил выбора порогов на 13
новых пациентах — подобранные пороги **не переносятся** (33–45% против 71–79% у
дефолтов); дефолты сохранены, оверрайд не рекомендуется.

**Инкремент 10 (сделано):** обученный детектор (градиентный бустинг, каузальные
признаки, потоковый двойник, Platt-калибровка, интеграция в пайплайн и монитор).
Пре-регистрированная проверка на 11 новых пациентах: оффлайн 0.94 при 8.9 FA/ч против
0.90 при 9.8 у порогового → **оффлайн-дефолт**; монитор 0.90 при 4.1 против 0.84 при 3.4
