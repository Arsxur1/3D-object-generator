# DECISIONS — ключевые инженерные решения NeuroLens

Живой журнал решений (ТЗ §0). Каждая запись: контекст → решение → обоснование →
последствия/альтернативы.

---

## D1. Объём первого прохода: фундамент + скелет (§18), не полный MVP (§17)

- **Решение:** реализовать §18.1–18.4 — структуру, контракты/схемы, конфиги,
  сквозной скелет на одном EDF — и остановиться на ревью.
- **Обоснование:** ТЗ (§0, §18) прямо требует инкрементальности; пользователь
  подтвердил этот объём. Меньше риска, ранняя обратная связь по архитектуре.
- **Последствия:** глубокие детекторы, приборные форматы, real-time, ML, PDF,
  топокарты — за интерфейсами/TODO, наполняются после ревью.

## D2. Контракты как единый источник истины (pydantic v2 → JSON Schema)

- **Решение:** все межслойные контракты — pydantic-модели в `contracts/`; JSON-схемы
  (`schemas/`) генерируются из них (`python -m neurolens.contracts.export_schemas`).
- **Обоснование:** одно определение, валидация на входе/выходе, «regulator-ready»
  трассируемость; схемы не расходятся с кодом.
- **Последствия:** схемы — артефакт сборки; при изменении моделей перегенерировать.

## D3. Лёгкое ядро (numpy/scipy) + `mne` как опциональный бэкенд

- **Решение:** Слой 3 (количественная ЭЭГ) и базовый DSP — на numpy/scipy;
  чтение EDF — `pyedflib`; `mne` подключается опционально (`.[mne]`) для ICA/
  геометрии монтажей/топокарт.
- **Обоснование:** ТЗ §14 рекомендует `mne`, но оставляет выбор («выбор за тобой»).
  Лёгкая установка, быстрые оффлайн-детерминированные тесты, прозрачные/аудируемые
  признаки (важно для регуляторики). «Слои — заменяемые модули за интерфейсами» —
  `mne` встаёт за тот же интерфейс (`ICAStep`) без переписывания.
- **Альтернатива:** сразу тянуть весь стек `mne` — тяжелее и избыточно для скелета.

## D4. Синтетический EDF как воспроизводимый вход

- **Решение:** детерминированный генератор (`data/synthetic/make_synthetic_edf.py`)
  с внедрёнными паттернами; пайплайн также принимает реальный EDF.
- **Обоснование:** TUH/CHB-MIT требуют регистрации и могут быть недоступны из среды;
  подтверждено пользователем. Синтетика даёт офлайн, воспроизводимость и заранее
  известную «истину» для тестов детекторов и каузального слоя.
- **Последствия:** синтетика — фикстура, не физиологическая правда; реальная
  валидация sens/spec — на клинических наборах (§15) в v2.

## D5. Слой 6 — реальный Anthropic-LLM + детерминированный фолбэк

- **Решение:** `AnthropicProvider` (schema-constrained, tool-call) при наличии
  ключа; иначе/при ошибке — `DeterministicProvider`. Выбор — через `factory`.
- **Обоснование:** пользователь выбрал «подключить реальный LLM». Но пайплайн и
  тесты обязаны быть детерминированными и работать оффлайн, поэтому детерминированный
  провайдер — дефолт без ключа и единый фолбэк.
- **Заземление:** оба провайдера проходят `validate_grounding`; что не привязано к
  `evidence`/ребру графа — отбрасывается (§9, §16). LLM физически не может добавить
  находку, которой нет в графе Слоя 5, в итоговый протокол.

## D6. Детекция и интерпретация разделены (Слой 4 «что» vs Слой 5 «почему»)

- **Решение:** Слой 4 выдаёт события с `evidence`/`confidence`; каузальность,
  физиологичность и правдоподобность — только Слой 5 (rules-engine + граф).
- **Обоснование:** прямое требование §7/§8; развязка упрощает замену детекторов на
  ML (v2) без изменения логики интерпретации.

## D7. База правил в YAML (не хардкод)

- **Решение:** каузальные цепочки — `configs/rules/neuro_rules.yaml`, валидируются
  `RuleBase`/`RuleChain`. 4 обязательные цепочки (§18.3) + ещё несколько.
- **Обоснование:** §0/§8 — знания нейрофизиологии конфигурируемы; правки не требуют
  изменения кода. Разведение ЭКГ-артефакт↔IED выражено как правило `resolves_artifact_for`.

## D8. Критические находки — отдельный жёсткий модуль (§10)

- **Решение:** `critical/safety.py` сканирует события независимо от LLM/режима;
  флаги всегда попадают в отчёт. Приоритет — чувствительность.
- **Обоснование:** «нельзя пропустить» должно быть неподавляемым и не зависеть от
  генеративной части. Электроцеребральное молчание НЕ автоутверждается (контекст
  смерти мозга вне области) — вместо этого флаг выраженной супрессии с оговорками.

## D9. Режим B — гейтирование, а не смелость

- **Решение:** `evaluate_mode_b_gate` требует порогов уверенности, качества сигнала,
  доли артефактов и правдоподобности; иначе — эскалация. Критические находки
  сообщаются всегда, гейт управляет лишь утвердительным заключением.
- **Обоснование:** §2 — автономность безопасна только при выполненных условиях.

## D10. Монтаж-движок как «вид», без пересчёта детекции

- **Решение:** детекторы работают на референциальном/усреднённом сигнале; монтажи
  (double banana и др.) — производные представления для отображения/локализации.
- **Обоснование:** §5 — переключение монтажа без пересчёта; биполярные разности не
  зависят от референса.

## D11. PD vs RDA — разделение по остроте (инкремент 2)

- **Решение:** периодические разряды (PD: GPDs/LPDs/BIPDs) детектируются по **острым**
  транзиентам (высокий порог z 2-й производной), ритмическая дельта (RDA: GRDA/LRDA) —
  по гладким ритмам (эпоховые признаки domfreq/concentration). Периодичность —
  по **самому длинному участку с постоянным межразрядным интервалом** (локализация во
  времени), а не по глобальной регулярности.
- **Обоснование:** клиническое различие PD и RDA — острота морфологии; локальные
  паттерны нельзя ловить глобальной статистикой по всей записи.

## D12. Генерализованная burst-suppression + утечка среднего референса (инкремент 2)

- **Решение:** burst-suppression детектируется по **среднему огибающих всех каналов**
  (генерализованность), а не по одному каналу. Периодические разряды фильтруются по
  **амплитудной выраженности** (≥60% максимума) и совпадению во времени.
- **Обоснование:** истинная burst-suppression генерализована — так убираются ложные
  срабатывания на одиночном тихом канале. Средний референс «размазывает» очаговый
  разряд на все каналы (реальный эффект); амплитудный фильтр восстанавливает
  латерализацию (LPDs не читаются как GPDs). Полная референс-инвариантная локализация
  (биполярные монтажи) — v2.

## D13. Extreme delta brush — корреляция beta с волной дельты (инкремент 2)

- **Решение:** «щётки» EDB выявляются по корреляции огибающей beta (18–30 Гц) с
  **сигналом** дельты (1–4 Гц), а не с её огибающей.
- **Обоснование:** огибающая устойчивого дельта-ритма постоянна; щётки «сидят» на
  гребнях волны, поэтому beta коррелирует с мгновенным значением дельты, не с амплитудой.

## D14. ЭКГ-артефакт исключается из периодической детекции (инкремент 2)

- **Решение:** каналы, контаминированные ЭКГ, и периодичность, совпадающая с ЧСС,
  исключаются из детекции периодических разрядов; иктальный детектор отделяет судороги
  от ритмической дельты порогом частоты (>3 Гц) или эволюции.
- **Обоснование:** ЭКГ-артефакт имитирует периодические разряды (§8.3); медленная
  неэволюционирующая ритмическая дельта — это RDA/IIC, а не иктальное событие.

## D15. Форматы вывода §11 — топокарты, граф, PDF (инкремент 3)

- **Решение:** топокарты — интерполяция per-channel скаляра (`scipy.griddata`) по 2D
  10-20-координатам из `configs/electrodes/coords_10_20.yaml` с контуром головы;
  визуализация каузального графа — `networkx` + matplotlib (цвет узла = физиология,
  толстая обводка = критический, подпись ребра = правило); изолированные
  артефакт-узлы (разрешённые спайки) скрываются. PDF — `reportlab` (Platypus),
  встраивает ключевые PNG.
- **Обоснование:** закрывает §11 (5,6,7) на лёгком стеке без `mne`; координаты — из
  конфига (не хардкод). Source-grade геометрия/топокарты `mne` — v2.

## D16. Кириллица/узбекский в PDF — шрифт DejaVu Sans (инкремент 3)

- **Решение:** регистрируем системный `DejaVuSans.ttf` (находится через
  `matplotlib.font_manager`) как Unicode-шрифт reportlab; заключения RU/UZ рендерятся
  им. Проверено: шрифт содержит нужные глифы (кириллица + узбекские модификаторы),
  reportlab измеряет строки корректно.
- **Обоснование:** стандартные шрифты reportlab (Helvetica) не покрывают кириллицу;
  DejaVu доступен на Linux и в поставке matplotlib (уже зависимость).

## D17. Real-time источник — повтор EDF по умолчанию, LSL опционален (инкремент 4)

- **Решение:** `StreamSource` (ABC) с конкретным `EdfReplaySource` (повтор EDF окнами,
  режим wall-clock или «быстро»); `LslStreamSource` — за `pylsl`, guarded (нет
  liblsl → понятная ошибка). Буфер окон `WindowBuffer` — кольцевой, overlap = window−step.
- **Обоснование:** `liblsl` недоступен в среде; повтор EDF даёт оффлайн-детерминированный
  тестируемый поток. Монитор транспортно-независим — LSL встаёт за тот же интерфейс (v2).

## D18. Потоковая детекция судорог — скользящий базлайн (инкремент 4)

- **Решение:** иктальный детектор в потоке использует **внешний скользящий базлайн**
  (медленный EMA per-channel RMS по истории потока), а не медиану внутри окна. Монитор
  ставит `IctalRhythmDetector.external_baseline` перед детекцией окна и обновляет EMA после.
- **Обоснование:** когда судорога заполняет 30-с окно, внутриоконной «тишины» нет →
  относительный порог амплитуды не срабатывает. Медленный EMA (α=0.05) при старте судороги
  ещё отражает до-иктальный фон → надёжная детекция первых окон → тревога.

## D19. Контроль ложных тревог/час (инкремент 4, §16)

- **Решение:** три гейта в `AlarmManager` — персистентность (≥N подряд окон),
  рефрактерность (не дублировать тип в cool-off), лимит/час. Критические типы (§10)
  обходят лимит/час, но соблюдают персистентность+рефрактерность (не спамят каждое окно).
  К каждой тревоге — **фрагмент ЭЭГ** (PNG в монтаже) для верификации.
- **Обоснование:** alarm fatigue в ОРИТ — реальный риск; при этом «нельзя пропустить»
  (§10) не подавляется. На коротком клипе (6 мин) 3 истинных критических события дают
  ~30/час — метрика бюджета корректно это отражает (это истинные, не ложные, тревоги).

## D20. REST API — тонкий сервис над ядром + §12-требования (инкремент 5)

- **Решение:** FastAPI-приложение (`api/app.py`) — тонкие эндпоинты, вся логика в
  существующих `Pipeline`/`RealtimeMonitor` (без дублирования). §12: `deid.py`
  (деидентификация — имя файла → одноразовый `subject_id`-хэш, клинические поля
  сохраняются), `audit.py` (append-only JSONL без PHI, с версиями), версии в ответах.
  `feedback`-эндпоинт использует `FeedbackLogger` (§13). FastAPI — опциональный extra.
- **Обоснование:** §14 рекомендует FastAPI; §12 требует деид/аудит/версионирование и
  гибрид edge+cloud. Тонкий слой не размывает ядро; TestClient даёт оффлайн-тесты.
  `subject_id` (соль `NEUROLENS_DEID_SALT`) позволяет серийное сопоставление без PHI.

## D21. Калибровка уверенности — per-code temperature scaling из feedback (инкремент 6)

- **Решение:** `calibration/` — метрики ECE/MCE/Brier, `TemperatureScaler` (fit T по NLL
  через `scipy`, `p'=σ(logit(p)/T)`), `ConfidenceCalibrator` (температуры по коду события +
  pooled-default, JSON, identity-фолбэк), `from_feedback.build_calibration` (confirm→1/
  reject→0 + `model_confidence` из `FeedbackLogger`). Пайплайн применяет калибровку до
  каузального графа и gate режима B; `result_json.calibration` фиксирует применённое.
- **Обоснование:** §16 требует ECE ниже порога и надёжные пороги режима B/тревог; эвристический
  confidence детекторов некалиброван. Temperature scaling — стандарт, лёгкий (numpy/scipy),
  без обучаемых моделей. Замыкает петлю §13: правки нейрофизиолога → калибровка.
- **Последствия:** identity по умолчанию (без feedback ничего не меняется); реальные
  температуры появляются по мере накопления правок. Per-class ML-калибровка — v2.

## D22. Неонатальная специализация — aEEG-классификация + ПМВ-нормы (инкремент 7)

- **Решение:** классификация фона aEEG (Hellström-Westas CNV/DNV/BS/CLV/FT) по сырым
  верх./нижн. маржам (µV, добавлены в `AEEG`), детекция SWC (цикличность нижней маржи);
  маутрационные нормы по ПМВ в `age_norms.yaml` + методы `NormsEngine`;
  `NeonatalBackgroundDetector` (активен только при ПМВ) — категория+SWC+IBI+непрерывность,
  **возраст-зависимая физиологичность** (physiology.py: неонат. фон физиологичен, если
  соответствует ПМВ). Правила `neonatal_bs_hie`/`neonatal_inactive_severe` (critical).
- **Обоснование:** ТЗ §1 выделяет новорождённых и aEEG как first-class, §15 — как
  дифференциатор. Пороги категорий — стандартные (Hellström-Westas), клинически-варьируемая
  часть (нормы по ПМВ) — в конфиге. Демонстрация: одна запись физиологична у недоношенного
  (28 нед) и патологична у доношенного (40 нед).
- **Последствия:** маутрационные шаблоны — индикативные (TODO: курируемый неонатальный
  датасет §15); неонатальные судороги (фокальные, отличаются) и HFO — v2.

## D23. Валидация на реальных данных PhysioNet (инкремент 8)

- **Решение:** модуль `datasets/` — клиент PhysioNet на stdlib (кэш в `data/physionet/`
  (gitignored), проверка SHA-256 по `SHA256SUMS.txt`, повтор при обрыве, параллельная
  загрузка), парсеры аннотаций CHB-MIT (`chbNN-summary.txt`) и Siena (`Seizures-list`,
  переход через полночь, исправление опечаток часа с предупреждением). Скачивание — только
  явной командой `neurolens physionet fetch`; данные в репозиторий не попадают.
- **Обоснование:** ТЗ §16 требует чувствительность/FA-час/латентность на размеченных
  данных; синтетика не заменяет реальную ЭЭГ. CHB-MIT (ODC-By) и Siena (CC-BY 4.0) —
  открытые экспертно-размеченные базы.
- **Последствия:** первая встреча с реальными данными выявила проблему, невидимую на
  синтетике: иктальный детектор возвращал одно «лучшее» событие на запись, теперь —
  по одному на каждый временной кластер (несколько приступов в часовой записи).

## D24. Bipolar-архивы → точная средняя референция

- **Решение:** если ≥60% меток вида `A-B` (CHB-MIT), потенциалы восстанавливаются МНК по
  графу биполярных отведений с ограничением «среднее = 0» на каждой связной компоненте;
  это **точно** средняя референция по электродам компоненты. Компоненты < 6 электродов
  (цепочка Fz-Cz-Pz без связи с остальными) отбрасываются с флагом качества, а не
  «угадываются». Дубликаты (`T8-P8-0/-1`) усредняются МНК; невязка > 1 мкВ — флаг.
- **Обоснование:** весь пайплайн (монтажи, топокарты, латерализация) работает на
  референциальных данных; повторное переотведение биполярных каналов как «электродов»
  дало бы бессмысленные производные.

## D25. Протокол оценки и обучения порогов

- **Решение:** событийная метрика OVLP (детекция пересекает [onset−30с, offset+60с];
  слияние детекций с зазором <10с), латентность — до момента, когда система «знает»
  (начало детекции оффлайн, конец окна тревоги в real-time). Подбор порогов — полный
  перебор сетки (360 комбинаций) на **обучающих пациентах**; критерий: макс.
  чувствительность при FA/час ≤ цели (по умолч. 1/ч), затем меньше FA, затем меньше
  латентность. Отчёт — на **других пациентах** (без утечки). Результат пишется в
  `configs/thresholds.physionet.yaml` (оверрайд, дефолты не меняются) и применяется
  флагом `--overrides`. Новый порог `ictal_min_channels` (пространственная
  распространённость) введён по данным: на chb01 confidence не различал истинные и
  ложные детекции (0.84–0.95 у обоих), а число каналов различало (≥5 против 1–2).
- **Обоснование:** прозрачное «обучение» — пороги физиологически интерпретируемы и
  проверяемы врачом; сравнимо с литературой по CHB-MIT. ML-детекторы — v2.
- **Последствия:** выборка мала (4 пациента); цифры — оценка, а не регистрационная
  валидация. Подробности и числа — `docs/validation_physionet.md`.

## D26. Отдельные рабочие точки: оффлайн ≠ real-time; оверрайд ≠ дефолт

- **Решение:** (1) монитор получает собственные пороги (`realtime.threshold_overrides`
  + persistence тревоги), подбираемые на «проигрываемых» трассах монитора — признаки
  окон и скользящая базовая линия пишутся один раз, детектор и `AlarmManager`
  воспроизводятся (≈0.2 с/ч вместо 2–3 мин/ч; побитово совпадает с живым монитором);
  (2) обучение может смешивать базы (`siena:PN00`); (3) подобранные пороги —
  **опциональный оверрайд** `configs/thresholds.physionet.yaml`, дефолты не меняются.
- **Обоснование:** на отложенных пациентах оффлайн-пороги в мониторе теряли приступы
  (10/10 → 7/10), детские пороги — взрослые приступы (6/6 → 5/6). На смешанном тесте
  подбор снижает FA/ч в 5–11 раз, но пропускает 1–2 из 15 приступов; для ОРИТ (§10)
  чувствительность важнее, поэтому дефолт остаётся чувствительным.
- **Последствия:** выбор правила отбора, «тратящего» бюджет FA на запас
  чувствительности, — гипотеза, проверяемая только на новых пациентах (текущий тест
  уже использован). Числа — `docs/validation_physionet.md`.

## D27. Пре-регистрация проверок и отказ от глобально подобранных порогов (инкремент 9)

- **Решение:** правила выбора порогов (strict/robust/margin), замороженные пороги,
  отбор новых пациентов (по размеру, без учёта качества; chb21 исключён как тот же
  ребёнок, что chb01), гипотезы и правило решения зафиксированы в git до загрузки
  тестовых данных; анализ — кодом `evaluation/prereg.py`, закоммиченным до результатов.
  По итогам (чувствительность подобранных порогов 33–45% против 71–79% у дефолтов на
  13 новых пациентах) дефолты не меняются, оверрайд помечен как нерекомендуемый.
- **Обоснование:** инкремент 8 подобрал и проверил пороги на 7 «удобных» пациентах;
  лишь проверка на заранее заданной новой выборке показала переобучение. Без
  пре-регистрации соблазн подстроить правило под тест сделал бы числа недостоверными.
- **Последствия:** следующие улучшения детектора (пациент-специфическая адаптация,
  артефакт-устойчивые признаки, ML-детектор) проверяются тем же протоколом на
  пациентах, не использованных ни в обучении, ни в прошлых тестах. Инфраструктура:
  глобальный лимит соединений к PhysioNet (троттлинг при ~18), планирование
  параллельной обработки по памяти (OOM на длинных записях).

## D28. Обученный детектор: деревья в JSON, каузальные признаки, две модели (инкремент 10)

- **Решение:** иктальный детектор как градиентный бустинг по 23 каузальным признакам
  эпохи; амплитуда нормируется на собственную EMA-базовую линию канала (≈5 мин);
  признаки агрегируются по каналам (независимость от монтажа). Модель — JSON (узлы
  деревьев), исполнение — numpy, совпадение со scikit-learn проверено тестом;
  scikit-learn — только для обучения (extra `ml`). Отдельные модели для оффлайн-признаков
  и для потока эпох монитора; `StreamingFeaturizer` побитово равен оффлайн `featurize`.
  Включение по умолчанию — только по пре-регистрированному правилу (`configs/ml.yaml`).
- **Обоснование:** инкремент 9 показал, что фиксированные пороги (особенно кратность
  амплитуды) не переносятся между пациентами; нормировка на собственную базовую линию и
  обученная комбинация признаков решают это по построению. JSON вместо pickle — нет
  исполнения кода из файла модели, модель версионируется и читается. Отдельная
  real-time модель — краевые эффекты фильтрации у новейших эпох окна. LOSO на 20
  пациентах: бустинг сильнее логистической регрессии на 5–17 п.п. при равном FA.
- **Последствия:** морфологические признаки (спайки, line length) и калибровка
  вероятности — следующие шаги; модели переобучаются командой из истории инкремента
  при росте числа пациентов, каждое переобучение — с новой пре-регистрацией.

## D29. Решение по инкременту 10: обученный детектор — оффлайн-дефолт, монитор — пороговый

- **Решение:** по пре-регистрированному правилу (применено кодом
  `evaluation/prereg10.apply_decision`, без ручного выбора): `configs/ml.yaml`
  `offline.enabled: true`, `realtime.enabled: false`; тихий режим B не предлагается.
  Обученный детектор в мониторе остаётся опцией (`RealtimeMonitor(learned=True)`).
- **Обоснование:** на 11 новых пациентах (170 ч, 108 приступов) оффлайн-модель находит
  больше приступов при меньшем числе ложных тревог (0.94 при 8.92/ч против 0.90 при
  9.78/ч); монитор с обученной моделью чувствительнее (0.90 против 0.84), но даёт больше
  ложных тревог (4.08 против 3.43/ч), а правило требовало «не больше». Пост-хок
  наблюдение (без chb10 — выигрыш и по ложным тревогам) — гипотеза для новой проверки,
  а не повод переписать решение задним числом.
- **Сопутствующие изменения:** поблочная обработка записей > 2 ч и float32-источник
  воспроизведения (ограничение памяти; результат идентичен — тесты); объединение
  критических находок по коду (несколько событий → одна находка со ссылками на все
  события; «продолжающийся приступ» поглощается «подозрением на статус»).
- **Последствия:** синтетическое демо теперь показывает события обученного детектора
  (обучен на реальной ЭЭГ; на синтетике отмечает и замедление — синтетика не
  характеризует клиническое качество). Монитор: следующая пре-регистрация — обученная
  модель с учётом младенческой ЭЭГ на пациентах, не использованных ни разу.

## D30. Решение по инкременту 11: обученный детектор v2 — дефолт и оффлайн, и в мониторе

- **Решение:** по пре-регистрированному правилу (`evaluation/prereg11.apply_decision`,
  без ручного выбора): `configs/ml.yaml` — оффлайн и монитор на моделях v2
  (`ictal_gbm_{offline,realtime}_v2.json`, точки A: 0.3/15 и 0.7/5), калибровка Platt
  v2. Пороговый детектор доступен явно (`learned=False`).
- **Обоснование:** на 6 последних неиспользованных пациентах (33 приступа) монитор v2
  нашёл 0.70 при 3.30 FA/ч против 0.52 при 4.08 у порогового (H1 подтверждена); оффлайн
  v2 0.88 при 7.93 против v1 0.88 при 8.06 и порогового 0.58 при 10.16 (H2, H3
  подтверждены). Независимо: на объединённых 17 новых пациентах инкрементов 10–11 v1 в
  мониторе 0.85 при 3.54 FA/ч против 0.77 при 3.71 у порогового.
- **Оговорки (зафиксированы, решения не меняют):** тест мал; v1 в мониторе на этом
  тесте тише v2 — выигрыш переобучения в мониторе не доказан; билатеральные
  тонико-клонические приступы (PN10) обученный монитор находит хуже порогового; у
  младенцев (chb06, chb10) больше ложных тревог.
- **Сопутствующие изменения:** калибровочный файл следует за выбранной моделью;
  возобновляемая оценка `ml-eval --stream-cache` (перезапуски контейнера прерывали
  многочасовое воспроизведение; результат детерминирован и проверен тестом).
- **Последствия:** открытые данные CHB-MIT и Siena с приступами исчерпаны — следующая
  проверка требует новой базы и новой пре-регистрации; дальнейшие улучшения (младенцы,
  тонико-клонические, длительность статуса) отрабатываются на обучающих данных по LOSO.

## D31. Новорождённые: маршрутизация детектора по возрасту (инкремент 12)

- **Решение:** раздел `neonatal:` в `configs/ml.yaml` (записан
  `evaluation/prereg12.apply_decision` по пре-регистрированным правилам): для пациента с
  указанным постменструальным возрастом оффлайн — пороговый детектор, монитор —
  неонатальная модель `ictal_gbm_realtime_neo1`; общая модель v2 к новорождённым не
  применяется. Явный `learned=` по-прежнему имеет приоритет.
- **Обоснование:** на 39 новых новорождённых (Helsinki, 146 консенсусных приступов) общая
  v2 находит 0.35/0.21 против 0.55/0.39 у порогового; неонатальная модель лучше порогового
  в мониторе (0.45 при 3.12 FA/ч против 0.39 при 3.48), хуже оффлайн (0.50 при 5.02
  против 0.55 при 4.66).
- **Сопутствующие изменения:** клиент Zenodo с MD5, эталон «консенсус трёх экспертов»,
  разбиение по правилу до загрузки ЭЭГ; чтение EDF с некорректным заголовком EDF+
  (`PlainEdfReader`).
- **Последствия:** выявление у новорождённых — около половины приступов; это ограничение
  в карточке модели и отчётах. Улучшение требует новых неонатальных данных и новой
  пре-регистрации.
